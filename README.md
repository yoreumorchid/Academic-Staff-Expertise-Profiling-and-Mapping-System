# Expertise Insight

Expertise Insight, an Academic Staff Expertise Profiling and Mapping System, is a full-stack platform enabling university faculty administrators to search, map, and benchmark academic staff expertise against course specifications and research grant calls. Also, it offers academic staff a convinient way to manage own academic records from publications to academic background.

## Features

### Implemented

| Module | Description |
|--------|-------------|
| **User Authentication** (UC-1–4) | Registration with ORCID linkage, admin approval workflow, JWT-based login, password reset via email |
| **Role & Portfolio Management** (UC-6) | Dual-role support (Academic Staff + Faculty Administrator), portfolio-based sidebar navigation |
| **Email Notifications** (UC-5) | SMTP-backed notification dispatch for registration status and password resets |
| **Staff Directory** (UC-7) | Searchable directory with filtering by name, department, expertise tags, and publications |
| **ORCID Sync** (UC-8, UC-12) | Automated publication harvesting from ORCID → OpenAlex, SciBERT-based embedding pipeline, quarterly/manual sync triggers |
| **Publication Abstract Supplement** (UC-9) | Manual abstract entry or PDF/DOCX upload to enrich publications missing metadata |
| **Academic Background** (UC-10) | CRUD for education, appointment, award, and service records; CSV bulk import/export |
| **Expertise Tag Refinement** (UC-11) | AI-generated tag validation, removal, and custom label addition with real-time embedding |
| **Course & Grant Mapping** (UC-13–14) | Two-stage semantic matching pipeline: cosine similarity coupled with spreading activation across the tag co-occurrence graph |
| **Portfolio Export** (UC-18) | One-page PDF/DOCX expertise snapshot generation |

## Tech Stack

| Layer | Technology |
|-------|------------|
| **Frontend** | React 18, TypeScript, Vite, Tailwind CSS, Zustand, React Router v6 |
| **Backend** | Python 3.11+, FastAPI, SQLAlchemy 2.0 (async), Alembic, Pydantic v2 |
| **Database** | PostgreSQL 14+ with asyncpg driver |
| **NLP / AI** | Sentence-BERT (`all-MiniLM-L6-v2`) for embeddings, SciBERT for publication analysis, LangChain + OpenAI-compatible LLM (I'm using DeepSeek) for report summarization |

## Local Deployment

### Prerequisites

- **Python 3.11+**
- **Node.js 18+**
- **PostgreSQL 14+** (running locally or via Docker)
- An **SMTP relay** for email notifications (e.g., Gmail app password, Mailtrap, or SendGrid)
- (Optional) **ORCID / OpenAlex / IEEE Xplore** network access
- (Optional) An **OpenAI-compatible LLM endpoint** for mapping report summaries

### 1. Database Setup

Create a PostgreSQL database (default name: `expertise_insight`):

```sql
CREATE DATABASE expertise_insight;
```

### 2. Backend Setup

```powershell
# Navigate to backend directory
cd backend

# Create and activate virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1    # Windows PowerShell
# source .venv/bin/activate      # macOS / Linux

# Install dependencies
pip install -e .

# Create environment configuration
New-Item -Path .env -ItemType File   # Windows PowerShell
# touch .env                          # macOS / Linux
```

Edit `.env` with your configuration values:

```env
# Application
app_env=development
app_debug=true
app_host=0.0.0.0
app_port=8000
app_cors_origins=http://localhost:5173

# Security
jwt_secret=<generate-a-random-string-at-least-32-chars>
jwt_algorithm=HS256
jwt_access_ttl_minutes=10080

# Database
database_url=postgresql+asyncpg://postgres:<password>@localhost:5432/expertise_insight

# SMTP
smtp_host=smtp.gmail.com
smtp_port=587
smtp_username=<your-email>
smtp_password=<your-app-password>
smtp_from=<your-email>
smtp_starttls=true

# Frontend
frontend_base_url=http://localhost:5173

# External APIs (optional — sync and benchmarking require these)
orcid_api_base=https://pub.orcid.org/v3.0
openalex_api_base=https://api.openalex.org
openalex_mailto=<your-email>
ieee_xplore_api_base=https://ieeexploreapi.ieee.org/api/v1/search/articles
ieee_xplore_api_key=<your-api-key>

# LLM (optional — mapping report summaries require this)
llm_provider=openai
openai_api_key=<your-api-key>
openai_api_base=<optional-custom-endpoint>
llm_model=gpt-4o-mini

# Embedding model
embedding_model=sentence-transformers/all-MiniLM-L6-v2
```

### 3. Run Database Migrations

```powershell
# Apply all pending migrations
alembic upgrade head
```

### 4. Start Backend Server

```powershell
uvicorn app.main:app --reload
```

The API is now running at `http://localhost:8000`.  
Interactive API documentation: [`http://localhost:8000/docs`](http://localhost:8000/docs)

### 5. Frontend Setup

Open a **new terminal**:

```powershell
cd frontend
npm install
npm run dev
```

The SPA is now served at `http://localhost:5173` and proxies `/api` requests to port 8000.

### 6. First-Time Setup Notes

- **First user registration**: The first registered user will have `PENDING` status. An existing administrator must approve the registration from the Admin → Registrations page (UC-2).
- **Initial ORCID sync**: After registration and approval, academic staff can trigger their first ORCID publication sync from their profile page (UC-12).
- **Embedding model**: The first API call that requires embeddings will download the Sentence-BERT model (~90 MB). This happens once at startup and may take 30–60 seconds.
- **LLM configuration**: The mapping report summary (AI-generated interpretation of top-3 matches) is optional — the system gracefully degrades if no LLM is configured.
